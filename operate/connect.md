# 真机无线连接指南(adb)

本目录下的 GUI 脚本(`gui_agent_install_app.py`、`check_delete.py`)都通过 adb 控制手机。
以下是如何用 **无线调试** 把手机连上电脑的步骤。

---

## 0. 一次性准备

1. 手机打开「设置 → 关于手机 → 版本号」, 连点 7 次, 打开 **开发者选项**。
2. 「设置 → 系统 → 开发者选项」里打开:
   - **无线调试**(Android 11 及以上, 推荐)
   - **USB 调试**(备用)

> 电脑上的 adb 需在 PATH 中; 未加入 PATH 时可用绝对路径(见下文)。
> 手机与电脑必须连 **同一个 WiFi / 同一局域网**。

---

## 1. 无线连接步骤(Android 11+)

1. 手机进入「开发者选项 → 无线调试」, 打开开关, 再**点进「无线调试」**那一行进入详情页。
2. 详情页顶部会显示 **IP 地址和端口**, 例如:
   ```
   192.168.1.100:37777
   ```
   这是**连接端口**(稍后用)。

3. 点「**使用配对码配对设备**」, 会弹出一个窗口, 里面有:
   - **配对码**(6 位数字)
   - **IP 地址与端口**(配对用), 例如 `192.168.1.100:36666`

   ⚠️ **配对端口和连接端口不一样**, 配对端口是临时的一次性端口。

4. 在电脑终端执行配对(输入弹出的配对码):
   ```bash
   adb pair 192.168.1.100:36666
   ```
   按提示输入 6 位配对码后回车, 显示 `Successfully paired` 即成功。

5. 配对成功后, 再用**连接端口**建立连接:
   ```bash
   adb connect 192.168.1.100:37777
   ```

6. 验证是否连上:
   ```bash
   adb devices
   ```
   输出中应看到:
   ```
   192.168.1.100:37777    device
   ```
   `device`(而不是 `unauthorized` / `offline`)表示连接成功。

---

## 1.4 USB 连接方法(最稳定, 推荐长期使用)

无线连接容易因锁屏、网络波动而掉线; USB 连接基本不会断, 适合长时间跑脚本。

1. 手机开启「开发者选项 → **USB 调试**」开关。
2. 用 **支持数据传输** 的 USB 数据线(不是纯充电线)连接手机和电脑。
3. 手机弹窗「允许 USB 调试吗?」, 勾选「始终允许使用这台计算机进行调试」后点 **允许**。
   - 如果没有弹窗: 拔插一次数据线, 或先执行 `adb kill-server` 再重新插线。
4. 验证:
   ```bash
   adb devices
   ```
   输出中应看到设备序列号且状态为 `device`, 例如:
   ```
   12345678    device
   ```
   `device`(而不是 `unauthorized` / `offline`)表示连接成功。

> 常见问题:
> - **列表里没有设备**: 检查数据线是不是纯充电线(换一根能传数据的线); 检查开发者选项里「USB 调试」是否打开。
> - **状态是 `unauthorized`**: 手机上没点「允许」授权框, 拔插重连后重新授权。
> - **Linux 服务器识别不到手机**: 可能缺少 udev 规则授权, 用 `lsusb` 看是否识别到设备; 若 `lsusb` 有但 `adb devices` 没有, 需要给手机厂商设置 udev 规则(见 [Android 官方文档](https://developer.android.com/studio/run/device))。
> - **同一时间 USB 和无线都连了**: 脚本默认用第一个设备, 建议只保留一种连接方式, 或运行时用 `--device` 指定序列号。

---

## 1.5 再次连接(已配对过, 无需重新配对)

配对关系是**持久**的: 只要手机上的「无线调试」开关仍开着、且没有在手机上删除这台电脑的配对记录, 以后连接都**不用再 `adb pair`**。

再次连接只需两步:

1. 手机保持「无线调试」开启, 进详情页看一眼当前显示的 `IP:端口`;
2. 电脑直接连接:
   ```bash
   adb connect 192.168.1.100:37777
   ```

> 注意: 手机重启、断开 WiFi 重新连网、或关闭再打开无线调试后, **IP 和连接端口都可能变化**, 以详情页当前显示的为准, 直接 `connect` 新地址即可, 依然无需重新配对。

---

## 2. Android 11 以下(没有原生无线调试)

需要先插一次 USB, 然后:

```bash
adb tcpip 5555
adb connect 手机IP:5555
```

之后可拔掉 USB, 保持同一 WiFi 即可。

---

## 3. 常用命令

| 命令 | 作用 |
| --- | --- |
| `adb devices` | 查看已连接设备 |
| `adb pair IP:配对端口` | 首次配对(输入配对码) |
| `adb connect IP:连接端口` | 连接设备 |
| `adb disconnect IP:连接端口` | 断开设备 |
| `adb shell` | 进入手机 shell |

---

## 4. 常见问题

- **`unauthorized`**: 手机上弹出了「允许调试」授权框, 点 **允许**。
- **`offline`**: 手机锁屏或网络不通, 确认同一 WiFi, 重新 `adb connect`。
- **`adb pair` 失败**: 配对弹窗很快会过期, 请保持弹窗打开; 确认配对端口没抄错(配对端口 ≠ 连接端口)。
- **找不到 adb 命令**: 用 adb 的绝对路径代替 `adb`。
- **连接掉线**: 网络波动会导致无线连接断开, 直接重新 `adb connect` 即可(一般无需重新配对, 除非重启了无线调试)。
- **`No route to host` / ping 不通(服务器场景)**: 说明手机与服务器不在同一可直达网段。若手机拿到的是 `172.x.x.x` 这类地址, 可能与 Docker 网桥(常见 `172.17~172.31`、`10.250.x`)冲突, 流量会被送进 Docker 网络而不是物理网络。解决: 让手机连到与电脑处于同一物理网段的 WiFi, 再 `adb connect` 对应 IP。

---

## 5. 配合脚本使用

- 只有一台设备: 直接运行, 例如 `python check_delete.py`。
- 多台设备: 用 `--device` 指定序列号, 序列号就是 `adb devices` 里显示的那串(如 `192.168.1.100:37777`):
  ```bash
  python check_delete.py --device 192.168.1.100:37777
  ```
